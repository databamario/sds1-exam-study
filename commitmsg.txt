Shuffle: fresh seed per session, plus a Randomize button on the mock exam

Practice and the mock exam both used to deliver the same questions in the
same order on every visit. The shuffle was deterministic - the seed was
meant to be session-scoped, but st.session_state persists across reloads
on streamlit cloud, so the seed landed at 1 the first time and never moved.
random.Random(1).shuffle(pool) returns the same order every time, by
definition.

The fix is small in code and obvious in retrospect: at the first call in a
fresh session, generate a real random seed with random.getrandbits(64).
shuffled() is unchanged; it was already deterministic given a seed. Same
seed still produces the same order, so a teacher who wants to pin a paper
still can.

Mock exam gets a Randomize button next to the seed input. Practice's
existing "Shuffle again" button does the equivalent, so I just pointed it
at the new seed generator.

Behaviour verified end to end: three simulated fresh sessions produced
three distinct MC orderings; the same seed produced the same order both
times. Imports clean, suite green.
