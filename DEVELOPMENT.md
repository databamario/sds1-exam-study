## Running it locally

```bash
python -m venv .venv
source .venv/bin/activate        # Windows Git Bash:  source .venv/Scripts/activate
pip install -r requirements.txt
streamlit run app.py
```

Or, after the first install, `start.bat` on Windows / `./start.sh` elsewhere.

## The gates

Everything below must pass before a commit. Check the exit code, not the output.

```bash
python tools/check_all.py      # build + all gates, in the right order
```

which runs, in order:

```bash
python tools/build_bank.py         # rebuild data/questions.json
python tools/validate.py           # schema, counts, keys, R coverage, option format
python tools/verify_r.py           # run every R snippet
python tools/verify_numbers.py     # check every number a question asserts
python tools/test_scoring.py       # grading regression tests vs the official table
python tools/test_answer_format.py # the MC format rules
python tools/test_progress.py      # the browser-stored progress layer
```

`verify_citations.py` is deliberately **not** one of them: it needs the lecture PDFs and produces
a ranking, not a verdict, so it cannot pass or fail.

R is not on PATH here. It lives at `C:\Program Files\R\R-4.6.1\bin\Rscript.exe`, and both R gates
find it on their own.

### What each gate is actually for

Two of these exist because the first version of the R gate was decorative: it turned each snippet
into a string literal instead of running it, so invalid R reported PASS. Both are now proven to
fail — each was run against the bank as it stood before the check was added, and both reported the
real problems.

- **`verify_r.py`** really executes every snippet. Because most snippets are fragments lifted out
  of the lecturer's session, it prepends a fixture holding stand-ins for the objects the slides
  already define. That proves the code *runs and calls the right API*; it says nothing about
  values, because the values are synthetic.
- **`verify_numbers.py`** covers the values. Each check names a number the question claims,
  requires that claim to still be in the question text, and then either recomputes it in R or
  looks it up in the source slide. Editing a number in the bank breaks the check instead of
  silently passing it.
- **`validate.py`** also fails if an MC question loses its correct option, if an explanation
  contradicts its own answer key, if a written answer runs long, if a question refers to the
  course rather than to the statistics, or if a referenced figure file is missing.

A gate that can only fail is noise, and a gate that cannot fail is worse, so every rule is
checked twice: once that it catches the violation it exists for, and once that a correct bank
passes it.

## Answer-format rules

Position is a free guess for anyone who notices the pattern, and the shape of that free guess
depends on the question.

With **five options and two correct**, the giveaway is a *pair*: a student who always ticks (a)
and (b) is right on every question whose key happens to be {a,b}. With **four options and one
correct**, it is a single position. `validate.py` fails when one pair holds more than 20% of the
five-option questions, or one position more than 35% of the single-correct four-option ones.

Both limits come from the sample size, not from whatever the bank happens to do. This replaced an
earlier check that watched the position of the single *false* option instead: that was a different
game, and it only looked at questions with more than one correct option, so the single-correct ones
went entirely unchecked.

Current shape: **137** five-option questions with exactly two correct, **20** four-option questions
with one, and nothing with more than two correct anywhere. The most common key pair holds 13.2% of
the five-option questions, against an even spread of 13.6% across the ten possible pairs.

When you add a question, spread the key rather than letting it fall where it falls, and say *what*
is wrong in the explanation rather than naming a letter. An explanation that says "(d) is false"
silently becomes a lie the moment the options are reordered. Where an explanation does name a
letter, `validate.py` checks the name against the key.

`tools/rebalance_pairs.py` fixes a lopsided key distribution by rotating options. It refuses to
touch any question that refers to a position ("the first plot") or a letter ("so (c) is false"),
since rotating those would contradict their own text, and after writing it rebuilds the bank and
checks that every question kept its options, its true options, its stem and its explanation.

## The citation review

This is the one part of the app that is **not** fully checked, and it is the only open work.

`validate.py` proves every citation names a real lecture file and a page inside it — all 243 pass.
That is not the same as being the *right* page. Read by hand so far: 113 citations. 34 errors
found and fixed. The remaining ~130 have not been read, so **34 is a floor, not an estimate**.

`tools/show_citation.py` prints a question beside the text of the slide it cites, which is the only
thing that has found these. `validate.py` reports every one of them as perfectly formed.

The reading is done in score bands with `tools/verify_citations.py`, and the hit rate is measured
rather than assumed: 67% in the worst band, 28% in the next, then 0% in the band after that, then
38% on a probe of the band below, then 27% and 22% on the two batches that followed. The zero in
the middle is the reason the reading did not stop there — one empty band was a gap in the signal,
not the end of it, and the bands on either side both gave errors. About a third of any shortlist
is false alarm, where the slide says "quantitative" and the question says "numerical".

```bash
python tools/verify_citations.py                  # the 25 worst-matched citations
python tools/verify_citations.py --figures        # which slide each figure's questions cite
python tools/verify_citations.py --id L7-MC-016   # one question beside its slide
python tools/verify_citations.py --proximity      # citations whose content is on the next page
```

The dominant cause is structural: a question inherits its lecture's citation wholesale even when
the content belongs elsewhere, so one wrong page silently mis-cites every question sharing it.
Three questions about random variables sat in Lecture 4 citing a slide about drawing cards.

The commonest single cause is narrower and mechanically avoidable: the slide is split across two
PDF pages, and the cited one holds the statement of the problem while the *next* one holds the
code, the formula or the worked numbers. Forty-one questions sit on the first page of such a pair.

The page number is an **index into the PDF**, not the number printed in the slide footer. Reading
it as the footer scores 26% against the slides; reading it as an index scores 78%. There is no
systematic offset to correct in bulk, which is why every page was read by hand.

## Topics not to write questions about

Both are named in the syllabus and are **not** in the bank, because the lectures do not teach them:
linear regression (deferred to SDS2 three separate times — L1 p.13, L8 p.22, and Lecture 9 never
returns to it) and Bayes' theorem (appears on no slide; only the OpenIntro 3.5 reading assigned
to Lecture 4 puts it within reach). The mock exam's help-page question has the same problem: no
slide covers the anatomy of a help page, though L2 p.41 does cover packages and `library()`.

If a lecturer announces any of these will be tested, this app will not have covered it. Adding
questions for them would mean anchoring them to material the course does not contain.

## Sounds

The four interface sounds are WAV files in `assets/sfx/`, generated by `tools/make_sfx.py` from one
source recording, and embedded into `src/sfx_data.py` by `tools/build_sfx.py`. They are played by
`celebrate.flush()`, which is called once at the end of `app.py`.

`src/sfx_data.py` is generated. Never edit it by hand — edit the WAVs and re-run
`python tools/build_sfx.py`. `check_all.py` fails if it is stale relative to the WAVs.

Do not reintroduce a `static/` directory or `server.enableStaticServing`. It was tried, and it
does not serve the files; see the postmortem in [DEPLOY.md](DEPLOY.md) for what happened and why.

## Regenerating the sounds

```bash
python tools/make_sfx.py     # rewrites assets/sfx/
python tools/build_sfx.py    # rewrites src/sfx_data.py
```

`make_sfx.py` cuts the long tail off the source, downmixes to mono, resamples to 16 kHz and sets
the peak, then derives the other three sounds by shifting its pitch, so they belong to one family.
